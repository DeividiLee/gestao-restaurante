# Gestão Financeira para Restaurantes Familiares

> Do caderno aos dados: ajudando pequenos restaurantes a entender a própria saúde financeira.

## O problema

Pequenos restaurantes familiares registram suas finanças em cadernos, blocos de
notas e sistemas soltos. As entradas até são anotadas, mas as saídas não — e o
dinheiro pessoal se mistura ao do negócio. O resultado: o dono nunca sabe se
realmente sobrou dinheiro no fim do mês.

Este projeto nasceu de uma dor real: o restaurante da minha mãe.

## Quem usa

- **Quem registra os dados:** atendentes, no caixa, durante o corre do dia e o dona do restaurante quando faz as compras.
- **Quem consome a informação:** dona do restaurante, que precisa
  decidir com clareza — não operar software.

## O que estou construindo (MVP)

O objetivo do MVP é o mínimo que gera valor real: capturar entradas e saídas de
forma rápida e mostrar, de forma simples, quanto o restaurante de fato ganhou.

- [ ] Registrar entradas (vendas) com canal, forma de pagamento e status
- [ ] Registrar saídas (gastos) com vencimento e separação pessoal/negócio
- [ ] Ver o saldo disponível e as contas pendentes
- [ ] Ver o total e a lista de entradas do dia

## Fora do MVP (backlog consciente)

Decidido adiar de propósito, para não inflar o escopo:
projeção de fluxo de caixa, CMV, ponto de equilíbrio, DRE, controle de estoque,
multi-estabelecimento, login/permissões e cálculo automático de taxas por canal.

## Como estou trabalhando

Projeto solo, com processo enxuto: quadro Kanban (não Scrum — não faz sentido
sozinho), histórias de usuário com critérios de aceite testáveis, protótipo antes
de código, e retrospectivas a cada 2–4 semanas documentando o que aprendi.
